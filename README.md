# Haazy 개인정보처리방침 · GitHub Pages

`index.html` 하나로 동작하는 정적 페이지입니다. CSS가 HTML 안에 들어 있어
별도 빌드, 서버, 패키지 설치가 필요하지 않습니다. GitHub 프로젝트 경로에서도
동작하도록 내부 링크는 문서 안의 앵커만 사용합니다.

현재는 **운영 정보 확인 전 초안**입니다. 실제 운영자·문의처를 임의로 만들지 않았으며,
확인되지 않은 보유 기간, 수탁업체, 삭제 절차 등은 노란색으로 표시했습니다.
아직 배포되지 않았고, Play Console에 제출할 수 있는 최종 방침도 아닙니다.

## GitHub Pages에 올리는 순서

1. GitHub에서 방침용 저장소를 만듭니다. 예: 조직 `DGSWASAP`의 `haazy-privacy`.
   GitHub Free에서는 공개 저장소로 Pages를 이용할 수 있습니다.
2. `index.html` 파일을 새 저장소의 **최상위 폴더**에 업로드하고 커밋합니다.
   서버 프로젝트 전체를 업로드할 필요는 없습니다.
3. 저장소에서 **Settings → Pages**를 엽니다.
4. **Source → Deploy from a branch**를 선택합니다.
5. **Branch → main**, **폴더 → /(root)**를 선택하고 **Save**를 누릅니다.
   기본 브랜치 이름이 다르면 파일을 올린 브랜치를 선택합니다.
6. 배포가 완료되면 Pages 설정 화면에 표시된 주소로 접속합니다.
   비로그인 창에서도 내용이 보이는지 확인합니다.
7. 아래 미확정 정보를 모두 반영한 정식 방침을 공개한 뒤,
   **게시된 웹페이지 주소**를 Play Console의 `개인정보처리방침 URL`에 넣습니다.
   앱 안에서도 같은 방침을 열 수 있는 링크를 제공합니다.

예를 들어 `DGSWASAP/haazy-privacy`에 기본 도메인으로 배포한다면 예상 주소는
`https://dgswasap.github.io/haazy-privacy/`입니다.
**이 주소는 배포 예시이며 실제 생성·접속 여부는 확인하지 않았습니다.**
GitHub 저장소 주소나 `blob/main/index.html`, `raw` 파일 주소를 제출하지 않습니다.

설정 방법: [GitHub Pages 게시 소스 설정 공식 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 정식 공개 전 확정할 내용

- 운영자 또는 팀 이름, 개인정보 보호책임자·담당 부서, 실제 문의 연락처
- 시행일, 변경 공지 방법과 기간
- 항목별 필수·선택 여부, 처리 근거, 동의 거부 시 영향
- 서버·DB·이메일 등 실제 처리업체와 위탁 범위, 국외 이전 여부와 내역
- 정보별 보유 기간, 파기 방법, 로그·백업의 보관 및 삭제 기준
- 앱 안팎의 실제 계정 삭제 요청 경로, 본인 확인 방법, 처리 기간 및 관련 데이터 삭제 범위
- 앱 권한, 앱에 포함된 외부 SDK와 자동 수집 정보
- 실제 이용 대상 연령, 아동 개인정보 처리 여부 및 필요한 절차
- 운영 환경의 HTTPS와 접근 통제 등 실제 적용된 보호 조치

확정 후 `index.html`에서 다음을 수정합니다.

1. 모든 `<mark class="todo">…</mark>`를 실제 내용으로 바꿉니다.
2. 초안 안내 상자, `작성 중인 초안` 배지 및 본문의 초안 설명을 정리합니다.
3. 시행일과 변경 이력을 반영하고, 페이지 설명에서도 `초안`을 제거합니다.
4. 검색 노출을 허용하려면 `robots`의 `noindex, nofollow` 메타 태그를 제거합니다.
   이 태그는 현재 문서가 초안이라 추가했습니다. 로그인·접근 제한 기능은 아닙니다.
5. Play Console의 데이터 보안 응답 및 앱의 실제 동작과 내용이 일치하는지 확인합니다.

## 서버에서 확인한 내용과 남은 확인 사항

- 계정: `User` 및 `UserDto`에서 학교 이메일, 이름, 닉네임, 비밀번호,
  내부 회원 번호, 등급, 가입·수정 시각을 확인했습니다.
- 소셜 로그인: `GoogleEmailVerifier`, `NaverOAuthClient`, `UserService`에서
  이메일과 제공자별 계정 식별자를 확인했습니다.
- 기능별 정보: 커뮤니티 게시글·댓글·좋아요, 심부름, 분실물, 채팅 관련 엔티티와
  메시지 처리 코드를 확인했습니다. 채팅 발신자는 현재 이메일을 사용합니다.
- 인증: 인증번호의 유효 시간은 1분, 가입용 토큰은 15분이며,
  가입 완료 시 인증 기록을 삭제합니다. 만료와 DB 기록 삭제는 별개입니다.
  가입하지 않은 인증 기록의 정기 삭제는 확인되지 않았습니다.
- 쿠키: 네이버 웹 로그인은 5분 유효한 임시 쿠키를 사용합니다.
- 서버 설정에는 Cloudtype DB 주소와 Gmail SMTP 기본값이 있지만,
  환경변수로 바뀔 수 있으므로 실제 계약·운영 업체라고 단정하지 않았습니다.
- 현재 확인한 회원 삭제는 관리자 API입니다. 일반 회원용 탈퇴 경로와
  계정에 연결된 게시물·채팅 등의 일괄 삭제는 확인되지 않았습니다.
  이 페이지를 만드는 것만으로 계정 삭제 기능이 생기지는 않습니다.
- 현재 작업 공간에서 앱 클라이언트 코드를 찾지 못했습니다.
  앱의 권한·SDK 및 실제 메뉴는 별도 확인이 필요합니다.

방침 작성 기준: [Google Play 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ko)

외부 서비스의 방침 링크를 열 때에는 인터넷 연결이 필요합니다.
